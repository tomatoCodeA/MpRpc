# MpRpc
构建一个分布式RPC网络通信系统，实在在分布式的环境中不同节点可以远程调用，选择muduo库作为网络通信框架，因为本身就是一个epoll加上线程池，很好的分离了网络代码和业务代码，one loop perthread模式，一个负载有accept连接，把连接分发到Stub中，后续所有操作都在Stub的线程中完成，充分利用CPU。使用protobuf进行数据的序列化和反序列化，相较于json和xml的文本存储，它是二进制格式，不存在额外的信息，网络传输效率更高。使用zookeeper作为配置中心进行服务发现和管理。

## 比较一下
**单机**  
各模块对硬件资源需求不同；并发量受限于硬件资源；模块的修改会导致整个项目重新编译

**集群**  
每台服务器独立运行一个工程所有模块，可以通过硬件扩充提高并发量，但是仍然存在各模块对硬件资源的需求不同，模块的修改也是需要全部重新编译，确实提高了并发量，但是部分模块并不需要高并发

**分布式**  
一种系统的部署方式，工程被拆分为多个模块，每个模块独立运行在一个节点上，所有的节点协同工作，每个节点还可以集群部署；但是在大型的工程中，模块间的界限不清晰，会出现重复代码，对于模块在不同的进程该如何访问，因此需要用到网络发送

**微服务**  
系统架构的设计方式，复杂的业务拆分为多个微小服务，每个服务可以单独运行和部署，之间是松耦合，每个微服务仅需要关注并完成一件任务，通过rpc进行通信，相较于rpc，服务之间的耦合度更低，微服务架构是分布式服务架构的子集

## RPC通信原理
客户端不需关注调用细节，就可以像调用本地应用程序中的对象一样调用在远程的某个服务对象
调用者通过Stub打包参数进行序列化，在zookeeper中服务发现，通过网络发送，服务端的Stub接收到解包参数进行反序列化，做本地服务，完成之后通过回调函数打包序列化发送回去，客户端反序列化得到结果。框架做的任务就是序列化和反序列化以及网络发送还有zookeeper。

## 一些笔记
Protobuf中，如果成员变量是另外一个类的对象，需要用mutable；编写proto文件的时候，如果是列表需要用到repeated关键字  
在使用Protobuf生成rpc方法的时候，**option**选项要记得定义，不然生成失败。在服务端需要使用的是Service基类，里边有方法和方法描述，都是虚函数，其中方法的参数有控制器，请求，响应，回调；在客户端生成Stub，所有的方法都是通过channel来调用call method实现。  
每个本地方法都是个微服务，和别的分离开来。  

使用框架就是先进行初始化，需要使用getopt读参数加载配置文件，因为是磁盘IO，所以读一次就行，配置也不会随时更改，单例模式（需要把所有的拷贝构造函数全部delete，不然偷偷摸摸的生成新对象，玩不转），创建发布者（网络服务对象Provider）进行专门发布服务，送到rpc节点上，使用Run（）启动节点，提供远程调用服务，这个地方是同步的，Run之后进入阻塞，等待远程调用。可以想办法优化为异步。  
Provider注册服务，通过Protobuf提供的Service和method记录表中，启动epoll+多线程的服务器，接受远程连接，通过on messgae解析填入请求响应，然后做本地业务

**日志模块**  
为了方便定位错误的地方，如果全都在控制台，长时间的使用显得太乱，不好定位
写日志是磁盘IO，所以不能在框架业务上去加日志，影响效率。
那就创个缓存队列吧，属于内存操作，再专门搞个线程写日志的磁盘IO。现在变成了多个线程写日志，线程安全必须保证一下，互斥机制试试，还需要线程通信，写日志的磁盘io线程别一直抢锁，要是队列为空的抢了也没用。

## 关于zookeeper
是Java开发的，处在2181端口，叫做分布式协调服务配置中心，像动物园一样，每个节点一种动物，程序员就是那个管理员。在不同的线程间还有线程的分布式锁，像什么互斥锁和自旋锁只在同一个线程内部有用。但是只把zookeeper当作了配置中心，因为需要知道分布式配置中心发布服务的ip地址和端口号，但没用别的功能。

！！！zk的数据怎么组织的？？   znode节点  每个节点1mb的大小

！！！zk的watcher机制    事件通知回调机制  看到更新了就动一下

节点：永久性节点，超时未发送心跳消息的话，zk不会删除节点，临时性节点会删除。服务用的永久性节点，方法用的临时性节点。不然方法挂掉了，还摆在那，就坏事了。这个心跳消息会以三分之一的timeout发送心跳

zk有单线程和多线程的版本，用的是多线程（异步），有三个线程：API调用线程，网络IO线程（ptread poll），watcher线程（pthread）。只有在调用成功只会才建立会话，不是发送了就创建会话然后在那等着

zk缺点：watcher是一次性的，每次触发都要重置一下；znode只存简单的字节数组，要是存对象，得自己转换
